# 手机端 Tend 工作区分组修复

## 问题与边界

正式手机端仍走 legacy 工作区列表，按仓库生成分类，没有执行桌面已有的 Tend 来源分离。同一仓库里的用户会话与 Tend 创建的任务因此混在一起。本次只修复列表投影，复用持久化 comment 标记，不改变会话、目录、仓库归属、协议或实验开关。

## 实施步骤

1. 从当前生产 fork 建立新的 fix 分支，保留已有分支与所有受保护引用。使用现有 Tend comment 识别器，为手机端生成独立的 `Tend tasks` 父分类及仓库/目录子分类。普通会话保持原分组、排序与置顶行为。
2. 在 occurrence 规划前阻断跨 Tend/普通来源以及 Tend 跨仓库的 lineage，防止祖先置顶或折叠带走另一类会话。Tend 行不进入普通 Pinned 分类，行为与桌面一致。
3. 复用桌面的 Tend 折叠键，父分类折叠时保留计数并隐藏子分类；搜索、仓库过滤、目录工作区、旧备注格式及不同分组模式都继续生效。手机端新旧列表路径使用同一明确标题，避免与名为 tend 的仓库混淆。
4. 添加能复现同仓库普通会话与 Tend 任务混排的回归，覆盖目录、折叠、搜索、过滤、pin 与 lineage 边界。运行手机端测试、类型检查、相关共享测试、changed 检查及 fork 维护检查；通过实际手机尺寸页面验证分组与折叠交互。
5. Review 修复提交后，以新的 fix 分支进入 fork hotfix candidate 流程。完整发布门禁通过、产物校验及最终 refs 核对完成后再报告发布完成；已有服务与手机安装状态独立记录。
